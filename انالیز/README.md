## ۱. معماری کلی برنامه
این اپلیکیشن بر اساس الگوی رسمی سیستم ویو اندروید (**Android View System**) با تفکیک وظایف زیر پیاده‌سازی شده است:
- **Presentation Layer (لایه نمایش):** فایل `activity_main.xml` وظیفه چیدمان المان‌های بصری، دکمه‌های ماتریسی، و نمایشگر دوخطی را بر عهده دارد.
- **Controller/Logic Layer (لایه منطق):** کلاس `MainActivity.java` تمام رفتارهای کاربر (کلیک‌ها)، نگه‌داری وضعیت محاسبه، اعتبارسنجی و عملیات ریاضی را مدیریت می‌کند.

## ۲. آنالیز ماشین حالت
ماشین‌حساب بر اساس یک ماشین وضعیت متناهی (Finite State Machine) ساده اما قدرتمند کار می‌کند:

```
[حالت اولیه: 0] 
     │
     ├─► فشرده شدن رقم ──► الحاق به currentNumber ──► نمایش در tvDisplay
     │
     ├─► فشرده شدن عملگر (+, -, ×, ÷) ──► انتقال currentNumber به firstNumber ──► ذخیره عملگر ──► نمایش در tvExpression
     │
     ├─► فشرده شدن مساوی (=) ──► دریافت secondNumber ──► اجرای محاسبه ──► نمایش نتیجه ──► تنظیم isResultDisplayed = true
     │
     └─► فشرده شدن C ──► ریست تمام متغیرها به حالت اولیه (Clear State)
```

### متغیرهای کلیدی:
* `currentNumber (StringBuilder)`: به جای استفاده از `String`، از `StringBuilder` استفاده شده تا الحاق و حذف ارقام بدون سربار حافظه اضافی در Heap انجام شود.
* `firstNumber (Double)`: به صورت کلاس Wrapper شیء‌گرا تعریف شده تا مقدار اولیه آن `null` باشد و بتوان تعیین کرد آیا عددی از قبل وارد شده یا خیر.
* `currentOperator (String)`: نگه‌داری نماد آخرین عملگر ریاضی انتخابی کاربر.
* `isResultDisplayed (boolean)`: این پرچم مشخص می‌کند آیا عدد روی صفحه نتیجه مساوی است یا عدد در حال تایپ. اگر نتیجه باشد، با فشردن اولین رقم بعدی، صفحه به طور خودکار پاک شده و عدد جدید شروع می‌شود.

## ۳. تحلیل منطق جاوا (`MainActivity.java`)

### الف) پیاده‌سازی `View.OnClickListener` به صورت متمرکز
به جای ساخت ده‌ها کلاس ناشناس (`new View.OnClickListener()`) برای هر دکمه، خود اکتیویتی اینترفیس را پیاده‌سازی کرده است:
```java
public class MainActivity extends AppCompatActivity implements View.OnClickListener
```
> **مزیت فنی:** کاهش تخصیص اشیاء در حافظه (Memory Allocations) و تمرکز تمام منطق رخدادها در یک متد واحد `onClick(View v)`.

### ب) متد الحاق رقم (`onDigitClick`)
- بررسی شرط `isResultDisplayed`: ریست بافر در صورت شروع محاسبه جدید پس از مساوی.
- فیلتر صفر پشت سر هم: اگر عدد ورودی تا کنون فقط "0" باشد، تایپ صفر بعدی جلوی نمایش "00" را می‌گیرد.

### ج) متد ممیز اعشار (`onDotClick`)
- تضمین رعایت اصول ریاضی: کاربر نمی‌تواند بیش از یک علامت اعشار (`.`) در یک عدد وارد کند.
- اگر عدد با ممیز شروع شود، به طور خودکار به صورت `0.` درج می‌گردد.

### د) متد محاسبات پیوسته (`onOperatorClick` & `calculateIntermediate`)
اگر کاربری بدون زدن دکمه مساوی، عملیات متوالی انجام دهد (مثلاً `5 + 3 × 2`):
- برنامه ابتدا حاصل عملگر قبلی (`5 + 3 = 8`) را محاسبه کرده، آن را به عنوان عدد پایه جدید ذخیره می‌کند و سپس عملگر بعدی را اعمال می‌نماید.

### هـ) قالب‌بندی خروجی (`formatResult`)
برای ارتقای تجربه کاربری (UX)، از نمایش صفرهای نامربوط اعشاری پرهیز می‌شود:
```java
if (value == (long) value) {
    return String.format("%d", (long) value); // 15.0 تبدیل به 15 می‌شود
} else {
    return String.valueOf(value);              // 15.75 به همان شکل اعشاری می‌ماند
}
```

## ۴. آنالیز رابط کاربری (`activity_main.xml`)
- **تم دارک به سبک کت‌پوچین (Catppuccin Macchiato / Material Design):** پس‌زمینه `#1E1E2E` با کنتراست ارگونومیک برای جلوگیری از خستگی چشم.
- **نمایشگر دوخطی:**
  - `tvExpression`: نمایش فرمول و عملیات در جریان (`24 ×`) با سایز ۲۲ واحد.
  - `tvDisplay`: نمایش عدد اصلی ورودی یا خروجی با سایز بزرگ ۴۸ واحد برای بهترین خوانایی.
- **چیدمان شبکه‌ای مبتنی بر وزن (Weight-based LinearLayouts):**
  - صفحه به دو بخش عمده تقسیم شده: نسبت `1.2` برای نمایشگر و `2.8` برای صفحه کلید.
  - هر سطر از دکمه‌ها دارای `layout_weight="1"` است که تضمین می‌کند در تمامی سایزهای صفحه و تبلت‌ها، دکمه‌ها با تناسب یکسان کشیده و مرتب باقی بمانند.
  - دکمه صفر (`btn0`) دارای `layout_weight="2"` است تا مانند ماشین‌حساب‌های حرفه‌ای، پهنای دو کلید را اشغال کند.

## ۵. مدیریت خطاها (Error Handling)
1. **تقسیم بر صفر (Division by Zero):**
   ```java
   if (secondNumber == 0) {
       Toast.makeText(this, "خطا: تقسیم بر صفر امکان‌پذیر نیست!", Toast.LENGTH_SHORT).show();
       return;
   }
   ```
   از بروز استثنای خطای ریاضی (`ArithmeticException`) یا تولید مقدار `Infinity` جلوگیری شده و با پیام Toast کاربر را آگاه می‌سازد.
2. **ورودی‌های ناقص یا کلیک‌های متوالی روی مساوی:**
   پیش از انجام هرگونه عملگر، وجود مقادیر `firstNumber`، `currentOperator` و طول `currentNumber` اعتبارسنجی می‌شود.

## ۶. تحلیل پیچیدگی (Complexity Analysis)
* **پیچیدگی زمانی (Time Complexity):** کلیه عملیات فشردن دکمه‌ها، پارس رشته به عدد و اجرای عملیات چهارگانه در زمان ثابت **$\mathcal{O}(1)$** انجام می‌پذیرد.
* **پیچیدگی حافظه (Space Complexity):** مصرف حافظه در سطح بهینه‌ترین حالت ممکن قرار دارد (**$\mathcal{O}(1)$**)، زیرا تنها چند متغیر عددی و یک شیء `StringBuilder` سبک نگه‌داری می‌شود.
